# 原生 Sheets 交付

处理模板、发布或恢复时阅读。目标是主Docx加Base/PCM更新两份原生在线明细；不画图，不以Excel导入重建表格。

## 数据与模板

完整原生统计及formatter执行后保存每窗发布数据，以请求、角色、VIN、环境、规则、制品证据和来源指纹绑定。使用原生占位符替换逻辑；每份模板数据独立读取或深拷贝，不能让Base原地替换后的矩阵复用为PCM模板。

模板默认由已批准外置源码的原生发布配置提供；可选 `report_delivery.native_template_spreadsheet_token` 也要通过结构/映射核验。复制原模板，不复制已填数的历史报告，不修改源模板。各子表按稳定ID或唯一名称映射，保留原合并、列宽、行高和文本格式。原生公式、空值及缺失诊断保持，不让数字替代其他字段。

图槽清空或保留原生诊断，不调用绘图和图片上传。在线模板没有占位符的规则不擅自扩布局；本地保留完整统计与未映射诊断。不能把模板旧指标空格解释成统计成功，也不能称原生七tab覆盖全部原字段。

## 身份与三资产

独立 `report_lark_profile` Bot创建/填两Sheet和主Docx。固定User继续用于规则读取、固定群版本查询和必要密级操作。每资产分别处理来源群view、请求者所有权、Bot full_access、L3和临时User授权回收；不能依赖Docx链接传播访问权。

主Docx使用 `assets/report-table.xml` 的无样例布局，数据来源段引用已确认的两Sheet。角色、时段、数值、Δ、颜色、单位与本任务快照一致，不把其他来源补到缺失处。在线写入成功回执后仍须按发布逻辑回读验证；回读和交付记录保留。

## 可恢复边界

复制意图、目标token、填数、回读及权限按步骤checkpoint。结果未知先核对，不自动创建第二份。失败保留已完成资产及本地发布快照，恢复只完成未完成步骤。新任务格式固定为 `docx_with_native_sheet_details`，`native_sheet_data`按两个角色绑定，不能为绕过发布失败退回旧附件交付。

旧 `completed` 不动；只有已保存 `docx_with_full_xlsx_attachments` 最终快照的旧未交付任务可继续附件补发，不查制品、不下载、不分析、不转Sheet。没有最终快照的旧任务需新来源消息重开。

原生发布不调用上游月份汇总、日志上传、规则写回或自动车辆回读。缺失来源、业务跳过及无状态样本仍按事实说明，不宣称补回了原始日志。

# 原走查独立调度与交互

新任务固定执行策略 walkthrough-lifecycle-v1。主入口在创建记录前核验专属任务服务、固定解释器、动作和脚本哈希，完整记录原来源和参数后再唤起服务；唤起结果未知保留真实队列，不冒充开始执行。Windows 任务服务独立于聊天进程，实际工作使用专用普通 Python，隐藏启动器不参与解析。

最多两个任务工作线程，一项完整取数/解析占用全局重型槽；另一项可处理已完成统计后的报告发布。任务内双时窗下载和完整统计预算不增加。两个时窗的环境发现并行，每窗各自 Prod→Test，任何查询异常不变成空结果；两窗查询与证据都完成后才下载。错误分支排空已有线程，来源证据仍完整留存。

新任务互斥使用固定文件上的操作系统锁，实际持有进程退出自动释放，不删除锁文件来解锁。活进程和未知旧锁不接管。服务重启发现已开始但没有持有者的任务，只归档旧状态并明确标记中断，不自动重新派发或下载。显式 resume 校验同任务后保存原状态，交回独立队列；已有完整结果复用原快照，只恢复发布。历史执行版本保留冻结入口及配置。

后台延后 45 秒观察实际阶段，阶段通知最少间隔 120 秒，只在业务阶段改变时普通回复来源消息，不新建话题。进度发送意图和回执存独立断点，结果未知不重复发；进度失败不阻塞分析。终态发送前结束进度线程，防止完成后又发“仍在处理”。成功仍要求原治理与真实来源送达凭证，失败由当前会话根据精确终态普通回复一次。

status/wait 提供脱敏阶段说明、排队前方任务数及已发送进度标记；不暴露其他任务身份、输入或报告。即时回执仍只由 CC Connect 发送。检查到已有后台进度凭证时，前台不再逐条转发阶段消息。

本版本只改变调度、查询重叠与交互，不改变完整统计、场景、边界、七子表、字段缺失、制品码及报告治理口径。离线并行测试证明两窗查询可重叠、异常分支排空、没有查询完成前的下载；真实时段总耗时须由之后的授权业务任务记录验证。

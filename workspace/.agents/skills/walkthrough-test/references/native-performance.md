# 受限并行与性能记录

本版优化完整走查测试的执行调度，不使用阿斯加德的固定平台结果替代逐窗车云数据。每个时段先完整查询 Prod，只有五类来源均明确成功且全空才查询 Test；同窗 AD、PCM、CPU 绑定同一个已选环境。查询异常仍失败，不作为空结果或切换依据。

## 原始输入与解析

两个时段继续独立并行。每窗先完成必需 AD 的四路有界下载并冻结来源指纹，然后启动一个 PCM/CPU 分支准备和解析，同时主分支执行完整 AD。PCM 下载不会与本窗 AD 下载叠加，单窗最多四路、整单最多八路文件传输，字节上限与逐文件恢复凭据保持。

Windows 不提供 Unix 负载平均数。原适配器会因此固定回退到两个解析进程；新适配器按 `max(1, min(4, cpu_count // 4))` 为每窗分配进程，未知核数使用一个。每窗实际请求值、兼容执行审计中的实际 spawn 值必须一致；任何未消费、超额或不一致的审计都停止接收结果。外部完整分析源码、原生提取、规则和统计函数不改变。

分支使用专用输入及缓存。解析期间暂不清理；控制线程等待自身所有分支结束后，按原保留策略依次清理。认证、响应或续签查询异常继续属于致命错误；普通 PCM 缺失/解析失败仍按既有缺失口径显示。AD 必需计算失败仍停止报告，已完成分支和故障诊断保留。回调只由控制线程发布，避免进度互相覆盖。

各窗记录 `ad_fetch`、`ad_analyze`、`pcm_prepare` 和 `pcm_parse` 的真实开始、结束、状态和耗时；这些区间可能重叠，不能相加当作总用时。读取旧线性阶段记录时保持原含义，不补造新时序。

## 完整模板读取

固定 User 的一次完整原模板快照可使用有界只读会话，持有既有同项目和 App 的可重入凭据锁，开始与结束都核验实际 App、User、有效期和授权状态。每条 API 仍限制在批准原模板与只读命令范围，并校验实际用户身份、manifest 与本任务绑定。会话不跨线程、任务、角色或读取目的复用；错误或超时不返回完整快照。

复制前的原模板权限重查和完整等价核对保留；Bot 创建、写数、全部值/公式/空白/格式/布局回读和逐资产治理不减少。原始统计、两张明细和主报告仍绑定本任务，未知复制或送达结果不重复执行。

新发布启用 `native_sheet_revision_guard=true`。Bot 的完整七子表快照在读取前后核对同一文档 revision；仅当版本稳定，且复制前或写入前的当前版本仍相同时，才复用同任务、同角色、同 token 的完整快照。版本变化、缺失、类型异常或接口不可用时恢复完整读取。固定 User 原模板读取会话及复制权限核验保持原样；写入后始终完整回读全部值、公式、空白、格式和布局，已交付表格恢复仍完整复核，不能通过旧 revision 覆盖手工改动。

稳定版本的两个角色合计减少48次重复读请求。只读验收中，同一份已交付表格完整快照为17次调用、约21秒；版本确认后复用为1次调用、约1.3秒，独立完整重读确认所有单元格、样式和布局一致。此数据仅表示重复读取阶段的收益，不能当作整单走查耗时。

## 验证边界

使用冻结旧版与新版对同一份有来源凭据的留存输入离线回放，核对全部统计行和主指标；该验证不创建业务任务、不发消息、不发布在线资产。单窗回放不能宣称已验证新的双窗线上完整流程。合成调度和身份测试用于确认并行、有限资源、失败排空及恢复守卫，实际云下载和飞书接口耗时仍须以后续真实请求为准。

# 完整 AD 来源下载的失败与恢复

本版保留逐窗 Prod→Test 选择。选定环境后，该窗 AD、PCM 与 CPU 不跨环境
补齐。成功空查询、列表查询失败和文件下载失败分别处理；列表返回文件并不保证
其下载服务已经可用。

## 有限下载诊断

下载 HTTP 400 立即失败，有限读取错误响应只识别固定错误码
`DOWNLOAD_FILE_FAILURE`，不改写下载地址、不跳过该文件。HTTP 401/403 保持原
权限错误。网络中断、HTTP 429 和 5xx 最多按既有上限尝试三次；耗尽后仍失败，
不能转为空结果或切换环境。

任务和逐窗流水线保留有界的错误分类、环境、HTTP 状态和尝试次数。普通回复
明确“日志文件下载失败，尚未完成分析”；不输出签名 URL、用户名、响应正文、
任意服务消息或堆栈。未知下载错误仍不假装成功。

## 新任务的逐文件凭据

首次 AD 下载前持久化与该窗请求、环境、来源策略及执行版本绑定的完整有序
对象计划。URL 签名不作为对象身份，因此同一对象刷新签名不改变计划。
每个文件完成字节数、ZIP 安全/CRC 与 SHA-256 校验后，单独原子保存完成凭据。
只有全部文件完成，才生成原有的完整 `download-manifest.json`。

对精确任务使用宿主 `resume --record` 时，重新核对选定环境的列表、计划与
每个已完成文件的校验凭据；校验通过的文件复用，其字节数仍计入原总预算，
仅下载尚未完成且本地不存在的文件。已完成窗口的统计继续走原有严格缓存验证。
任务仍要求所有必需 AD 来源齐全，恢复不代表可以忽略坏文件。

发现计划变化、身份/环境/版本变化、摘要变化、不安全路径、额外文件或无凭据
残留文件时停止并保留现场。包括文件原子落盘后、凭据尚未提交即进程退出的
狭窄窗口，也不自动吸纳或覆盖无凭据文件。处理这种现场需要明确核对，不能
根据文件名补造完成凭据。

本版不导入旧任务的半成品目录，不给旧版无逐文件凭据的已下载文件补造凭据。
旧结果仅按原绑定恢复交付；升级不重写历史记录、不自动重新计算或发送报告。

# Prod 列表成功空响应兼容

本次诊断使用同一获准端点、固定请求头、同一车云身份及当前业务的精确 VIN/时间窗，只做列表 GET；没有下载日志或创建在线报告。

实际对照中，Base 窗的五类 Prod 列表都返回 HTTP 200、整数业务码 200、`success: true`、`message: 操作成功！`、显式 `data: null`。同参数下 PCM更新窗的 Prod 五类列表正常返回分页对象，Base 窗的 Test 五类列表也正常返回。端点、认证方式及时间参数未发现与已有成功实现的差异。

此前走查客户端只接受 data 对象，因此将该成功信封判为结构异常。已有 AD/Uroad 客户端会将空 data 当作空结果，但也会吞掉缺失 data 等异常；新适配不沿用这种宽松处理，只识别经过实测的 Prod 首屏明确成功格式，并保存版本化兼容证据及请求级审计。该结论解释客户端兼容差异，不断言已经证实服务端内部产生 null 的原因。

Test 的 null、缺失 data、后续页 null、鉴权失败、失败标记、未知消息或存在错误字段的返回都不能按此兼容处理。兼容产生的空列表与原始 null 类型均保留来源证据；不能伪装成服务端本来就提供了 total 或列表。逐窗环境选择、完整分页、VIN/时段、规则指纹和三份资产交付守卫保持。

# 原模板读取身份与报告归属

本文件描述本地可选候选能力。它不代表目标已启用，也不授权创建云端模板或改变权限。

最终交付继续沿原流程：报告Bot创建主Docx和两份原生Sheets，写数并回读核验，逐份设置请求发起人为所有者、来源群只读及Bot管理权限，执行现有密级流程。不能让固定User直接创建最终业务报告以绕过Bot复制失败。

## 默认方式

`report_delivery.native_template_reference_reader` 不填或为 `bot` 时，仍由报告Bot读取原模板及可选覆盖模板。原v1断点保持，不读取bridge manifest，不自动切换身份。模板只允许管理者复制而Bot未获权时，按权限失败处理。

## 显式fixed_user候选方式

适用于已批准且核验完成的专用空白模板：固定User有原模板的合法查看和复制权，专用副本只对固定User及同项目报告Bot开放，报告Bot在该副本拥有管理和复制权。原共享模板的权限与内容不改。

将 `settings.template-bridge.merge.example.json` 的三个可选模板字段合入现有配置；这是局部示例，不能用它覆盖完整配置。`native_template_bridge_manifest` 必须是本工作区 `data/walkthrough-template-bridge` 内的普通文件，不放进身份目录，不得包含凭据。不得手工填上成功布尔来冒充在线准备完成。

该模式按固定User只读获取原reference并核实复制权，按Bot读取专用模板，完整比较七子表的值、占位、公式、样式和布局。通过后由Bot从专用模板复制两份业务结果。统计算法、formatter、数值映射、请求发起人归属均不改；不用Excel导入重建模板。

准备凭据和发布断点绑定项目、应用、固定User、两个profile、身份目录指纹、原模板和专用模板。身份、模式或manifest变化不能认领旧断点。新模式使用独立v2发布绑定；不能直接将已有v1任务改配置迁移。

准备阶段须真实核验报告Bot的open_id及其专用副本权限。运行时使用现有身份检查核验当前应用与专用bot-only profile，再只读获取当前Bot信息并与准备凭据中的open_id核对；按目标机实际返回的data.open_id解析。空数据、错误身份和不匹配均停止，不换身份或追加权限。只有实际核验成功才记fresh Bot身份通过。

## 恢复和更新

原模板或专用模板在复制前改变，等价核验失败即停止；不自动重新复制、同步、改权限或填入未知布局。重新准备专用模板需要明确操作范围及验证。

已有目标token、受检快照和写数计划时，只继续交付，不重新下载日志、计算统计或以新的原模板替代保存的证据。复制回执未知时保留pending，先人工核查已创建副本，不重复创建。

`prepare_native_template_bridge.py` 仅提供准备计划；它不能执行云端复制、授权或生成ready凭据。云端准备需在目标环境按确认计划完成实际读取、复制、权限及密级核验，任何未知检查都不能记作成功。

本地preflight不访问模板，不证明Bot能复制，也不代替三份实际资产的权限和接收端验收。

# 预检、既有凭据维护与启动

业务新请求直接使用工作区宿主 `start`。它在创建任何业务记录、日志查询、
版本查询或报告资产之前完成全部输入、来源绑定、执行开关、配置与本地预检。
独立 `preflight` 保留为只读诊断命令；不能把它当作新任务启动前必须由助手
另行执行并通过的入口，从而阻断 `start` 内已有授权的维护路径。

## 仅对明确过期的固定身份凭据进行维护

只读检查先确认预先配置的应用与固定 User。仅在两者均明确匹配后，发现
access token 明确为 expired，或可解析的到期时间已经过去，才返回有限的
`product_identity / user_token_refresh_required`。

新请求 `start` 遇到该唯一原因时，在已通过请求来源、输入、执行开关和静态
隔离校验的前提下，调用原有受控 `ensure_user_authorization`。这只验证或续期
既有授权，不发起 login、不新增 scope、不替换身份、不发送业务消息。
维护后必须重新完成整个本地预检，再进入原有 `start_job`。

身份或应用缺失/变化、未知认证状态、本地 CLI 不可用、维护失败、维护后
仍未通过预检，都停止，且不创建任务。若刷新授权确已失效，明确报告需要
原固定授权人处理；不让其他请求者代替固定身份，不静默开启新的 OAuth。

独立 `preflight`、`rules-check` 和旧来源的只读重投不因本版自动刷新。
`start` 中一次维护结束后不会无限重复维护；失败明确保留诊断。

## 有限的失败原因

预检阶段区分配置、解释器/依赖、车云配置与读取身份、规则、固定飞书身份、
原生分析环境和报告模板。错误只保存有限 `stage / reason` 和对应中文提示，
不输出异常原文、路径、用户名、token、CLI stdout/stderr 或认证响应。

“本地预检通过”只证明本机启动条件，不代表车云查询、下载、完整走查或报告
交付已经通过。报告任务只有经过原有完成与送达凭据检查后才能称为已交付。
